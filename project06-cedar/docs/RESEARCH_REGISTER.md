# Research register

Retrieved 2026-10-17 (America/Toronto). Only primary sources inform the format and implementation claims below. This register does not certify procurement or legal compliance.

| Question | Primary source | Claim supported | Design relevance and uncertainty |
|---|---|---|---|
| Which software inventory format is actually implemented? | [CycloneDX 1.6 JSON reference](https://cyclonedx.org/docs/1.6/json/), [official 1.6 schema](https://github.com/CycloneDX/specification/blob/1.6/schema/bom-1.6.schema.json) | CycloneDX provides a versioned JSON inventory schema. | CEDAR pins and vendors 1.6 even though newer specification versions exist. The complete official schema validates the supplied inventories offline. CEDAR only reasons about a small subset: component name, exact version, generic PURL and synthetic advisory/exposure evidence. Schema validity does not establish completeness. |
| How should concurrent writers be serialized? | [SQLite transaction documentation](https://www.sqlite.org/lang_transaction.html), page updated 2026-02-18 | SQLite has one simultaneous writer; BEGIN IMMEDIATE acquires a write transaction immediately. | CEDAR checks expected_revision and approval preconditions inside one write transaction. A busy timeout does not provide distributed coordination; this is a single-host prototype. |
| How can the API be tested without a deployed service? | [FastAPI testing guide](https://fastapi.tiangolo.com/tutorial/testing/) | FastAPI exposes an application testing client through Starlette. | Tests invoke actual application routes and dependency code. Browser checks and a fresh process launch complement these tests; in-process tests alone do not establish deployment behavior. |
| How should server-side identity be derived? | [FastAPI security first steps](https://fastapi.tiangolo.com/tutorial/security/first-steps/) | Authentication credentials must be verified by the backend before granting an identity. | CEDAR uses opaque local sessions and server role checks, with public demo passwords. It does not claim a production identity provider, OAuth deployment or real separation of personnel. |
| How is the browser demonstration captured? | [Playwright Python screenshots](https://playwright.dev/python/docs/screenshots), [video lifecycle](https://playwright.dev/python/docs/videos) | Browser contexts can save screenshots and record video; closing a context finalizes recording. | The repository captures the implemented local application with one Chromium build. Automated interaction is not a usability study. |
| Is a company-specific appendix justified? | User-supplied request | INKAS and Marconi are prospective audiences, not customers or partners. | Portfolio remains contractor-neutral. The exact legal entities and official websites have not been established; no company-specific activities or internal processes are asserted. Confirm the intended entity before tailoring. |
