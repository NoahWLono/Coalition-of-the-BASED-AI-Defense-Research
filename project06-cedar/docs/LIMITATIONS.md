# Implemented scope and limitations

CEDAR is a local synthetic prototype. The measured evaluation, screenshots and tests establish behavior within that scope. They do not establish performance on unseen customer files, user time savings, enterprise readiness or physical product capability.

Implemented: deterministic extraction in three labelled text layouts; source-version hashes and line citations; typed documentary gates; explicit conflicts/staleness; decimal fleet costs and open exposures; scored intervals, three preference profiles, five sensitivity scenarios and conservative dominance; CycloneDX 1.6 schema validation and bounded synthetic advisory dispositions; server roles and concurrency checks; immutable decision records; amendment impact and stale approvals; portable report/record/source verification.

The optional model proposal interface is declared but has no live model client. Live model output evaluation, OCR, arbitrary PDFs, spreadsheet ingestion, semantic claim extraction, general advisory-range resolution, remote vulnerability feeds, digital signing and formal proof are unperformed. No independent physical test, human benchmark annotation, customer review, penetration test or external audit is claimed.

Source layout recognition is deliberately explicit. A response outside the grammar may produce no assertion; missing support then remains unresolved. The requirement identifiers are provided by the supplier fixture rather than discovered semantically. This choice makes the baseline auditable but limits generalization. A pilot must measure coverage and error rates on representative permitted documents with human annotations.

The cost model preserves an undiscounted, pre-tax CAD baseline. It accepts quoted recurring escalation, a bounded planning horizon and replacement-rate assumptions. It does not estimate unknown charges, taxes, exchange rates, discount rates, inflation or insurance. Different fiscal treatments require explicit new policies. Unknown exposures have no finite upper bound.

Software identity matching is limited to the generic PURLs used by the fixtures and exact affected/fixed version lists. An inventory's validity does not establish completeness, a shipped version or exploitation. Supplier exposure statements are separately identified and can become stale. No real CVEs or exploit claims occur in the dataset.

Public demo passwords and local sessions demonstrate role restrictions at the server boundary; they do not authenticate real reviewers. Read endpoints are public to the local host. Sessions are in process memory and expire after eight hours; a restart requires sign-in again. No durable identity provider, tenant isolation, tamper-resistant audit service, encrypted document store, retention automation, backup service or production operational monitoring is implemented. The SQLite file and host are trusted. Total workspace growth is not quota-managed; individual uploads and requests are bounded. Use only synthetic material and loopback access.

All inputs conservatively invalidate old snapshots; selective dependency-based approval reuse is unimplemented. Hash manifests detect inconsistencies but can be regenerated by someone controlling the package. The embedded verifier itself needs a trusted distribution channel for adversarial use. Export status describes the workspace at export time and cannot detect a future remote amendment.

Browser checks use one Chromium build on this machine. Accessibility checks include keyboard focus, labelled controls, state words and narrow layouts; no formal accessibility conformance audit has occurred. The local review agents used AI systems, not independent people or empirical auditors.

Contractor-neutral materials use only the supplied audience context. Exact INKAS/Marconi legal entities remain unconfirmed. Legal, regulatory and export applicability must be assessed by an authorized specialist during any real pilot. CEDAR records evidence and decisions; it does not certify legal compliance.
