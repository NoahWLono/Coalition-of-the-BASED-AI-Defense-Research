# Prozorro comparable-purchase analyzer implementation plan

**Goal:** Deliver a reproducible fifty-lot comparability audit and conservative screening pipeline, with unresolved validation gates explicit.

**Architecture:** Python standard-library package, safe source extracts, typed stage observations, Decimal accounting, review-gated comparison, deterministic JSON/CSV/HTML report. Acquisition and normalization are separate so saved extracts reproduce without network.

**Spec:** ../../DATA_CONTRACT.md

**Constraints:** Local dedicated directory; no publishing, contacts, spend or host changes. Python 3.14 observed; support Python 3.11+. Serial acquisition at most one request per second, 30-second request timeout, 5 MB per response, 150 total acquisition requests. No sensitive locations or personal contacts in artifacts. APIs may return current state for historical publications.

## Tasks

- [ ] Source discovery and permission ledger. Check current official docs and inspect a handful of civilian lots. Record discrepancies from legacy docs. Obtain candidate identifiers without claiming a random sample.
- [ ] Core accounting. Write tests first for Decimal separators, thousand packaging, absent/masked quantities, tax uncertainty, mixed goods, cancellation, stage deduplication and amendments. Implement typed observations and normalization. Test correct conservative exclusions.
- [ ] Acquisition. Project whitelisted fields from public API; save content hashes, timestamps and references. Stop at fifty unique in-scope lots or a documented access/resource boundary. Save state for resume. Never claim fifty comparable purchases from fifty imported lots.
- [ ] Screening and evaluation. Add deterministic robust groups and minimum-size rule, exclusion ledger, evidence HTML, holdout review template and Wilson intervals. Verify synthetic known cases, null unlabeled metrics and assumption sensitivity.
- [ ] Reconciliation and review. Inspect a stratified assistant subset, independently recompute using Fraction, run regression tests, reproduce output hashes and request independent code review. Record human validation as unfinished if unavailable.

## Review focus

- Contract values paired with stale tender quantities must stay ineligible.
- Unknown delivery/tax/specification fields must not create a comparison group.
- Publication date must not be confused with feed modification order.
- Revisions and stages must not increase the unique purchase count.
- Zero independently reviewed records must never produce an estimated false-flag rate.

## Execution decisions

The user explicitly authorized implementation with reasonable reversible choices and no approval loop. A dedicated subdirectory isolates this project from the existing uncommitted project11 work. No commit or branch change is needed in the shared unborn repository. Track progress in evidence/progress.md.
